# 月度余额消费返利

入口：**订阅管理 → 月度返利**。

1. 选择已结束的月份，点击“核算所选月份”。核算只生成账单，不发放额度。
2. 按用户或状态筛选，打开“查看审核详情”，确认消费基数、比例和应返额度。
3. 点击“审核通过并发放”，创建一年有效、不周期重置的返利订阅；余额不变。
4. 已发账单可查看发放管理员、发放时间、订阅 ID、有效期及原始审核金额。

## 计算口径

- 以北京时间自然月、请求开始时间归属月份，时间区间为 `[月初, 下月月初)`。
- 只统计后付费结算记录中的余额净扣费 `WalletQuota`。同一请求后续退款或补扣会更新净额。
- 订阅额度消费、违规扣费不参与；余额充值、借款入账、订阅购买等也不属于 API 消费。
- 月消费 `S ≤ $750` 不返；`$750 < S ≤ $1500` 按整月消费返 5%；`S > $1500` 按整月消费返 10%。不叠加。
- 以美元额度计算，账单保存额度换算基准；返利四舍五入至最小内部额度单位。
- 计算结果超过系统支持的额度上限时阻止发放，标记待核对，不静默截断。
- 返利订阅被消费时属于订阅消费，不再次参与返利。

## 审核与一致性

每用户每月只有一张账单、至多一次发放。账单和订阅在同一数据库事务中写入，失败可重试；重复请求返回原发放记录。删除或撤销订阅也不会解除账单的已发标记。

发放接口携带管理员所审核的账单版本，并在事务中重新计算消费。金额或档位发生变化时，更新账单并返回 `REBATE_CHANGED`，管理员必须刷新后重新审核。

原始发放基数、比例、额度与发放人不可被重新核算覆盖。自动任务每小时重新核对已准备过的月份，**不会自动发放**。发放后退款或补扣导致应返额度变化时，账单标记“待核对”，显示最新应返额度与已发额度的差额，不自动追缴或补发。管理员通过关联订阅进行人工处理。

## 历史数据边界

核算依据主数据库中的后付费结算记录，不从可清理或独立存储的消费日志猜测资金来源。启用后付费结算前未记录资金拆分的历史消费不会被回填为余额消费。

旧版 Midjourney 失败退款会直接退余额，未更新原请求的结算记录。月份内存在已受理任务的这类失败记录时，账单标记待核对并阻止直接发放，避免高估返利基数。

## 接口

接口继承订阅管理的管理员鉴权；写操作使用来源校验、关键操作限流和管理员审计。

- `GET /api/subscription/admin/rebates?period=YYYY-MM&status=&user_id=&p=1&page_size=20`
- `POST /api/subscription/admin/rebates/recalculate`，请求：`{"period":"YYYY-MM"}`
- `POST /api/subscription/admin/rebates/:id/issue`，请求：`{"revision":1}`

新增 `monthly_rebates` 表和结算记录的请求开始时间索引，由常规迁移和快速迁移两条路径创建。

## 本月消费查询

个人钱包展示当前北京时间自然月的余额消费、订阅消费和合计。管理员可在 **数据看板 → 消费数据** 查看全部用户（含零消费用户），按用户名搜索并分页浏览，默认按余额消费降序。页面每分钟刷新，也支持手动刷新。

两处均读取主数据库请求结算净额，采用与返利相同的月份边界和违规扣费排除条件；个人接口始终限定当前登录用户，不接受其他用户 ID。历史上没有资金拆分结算记录的消费不在此统计中。

- `GET /api/data/monthly-consumption/self`
- `GET /api/data/monthly-consumption?keyword=&p=1&page_size=20`（管理员）
