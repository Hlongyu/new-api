# 个人分组与渠道审核

普通用户可在「个人分组」中创建 `custom-` 开头的分组并维护倍率，在自己的分组中配置渠道。管理员在「渠道审核」中批准或驳回提交的版本。

## 分组与计费

- 后端自动补齐 `custom-` 前缀；名称全局唯一，长度最多 64 字节，只允许小写英文字母、数字和连字符。名称和所有者不可修改。
- `custom-` 命名空间保留给个人分组，现有管理员分组不能被个人用户认领。
- 创建者可以修改说明和倍率，无需审核。倍率范围为 0–1,000,000，拒绝负数和非有限值。
- 个人倍率单独持久化，管理员保存系统倍率或执行系统倍率计划不会覆盖个人倍率。写入实例立即刷新；其他实例随现有 `SyncOptions` 周期刷新。
- 继续使用现有模型价格、用户分组特殊倍率、优惠券、预扣和结算规则。费用由调用方承担，包括所有者调用自己的分组。不产生自动分成或收益余额。
- 分组有已批准且启用的渠道后，进入普通用户可选分组。既有管理员可用分组限制仍然适用；不会自动加入全局 Auto 列表。

## 审核与发布

1. 保存配置产生不可变草稿版本，并使该渠道之前的草稿或待审核版本失效。
2. 所有者显式提交最新草稿，进入待审核。
3. 管理员核对已发布和提交版本的名称、类型、地址、模型、优先级、权重、启用状态，以及密钥是否变更。密钥不随列表或审核响应返回。
4. 批准时在同一数据库事务中更新线上渠道、能力表和审核状态。重复审批和审批旧版本均失败。
5. 驳回需要填写原因；原线上版本不受影响。再次修改后可以重新提交。

待审核配置不写入 `channels` 或 `abilities`，因此不会被缓存重建、自动路由或故障重试提前选中。普通渠道编辑和复制接口不允许改写个人渠道；管理员仍可通过现有运行状态接口紧急停用。

当前个人配置支持 OpenAI 兼容、Anthropic、Gemini、New API 四类上游，采用单 API 密钥和公开 HTTPS 地址。支持常规 HTTP 推理入口，包括流式响应；Realtime WebSocket、异步视频任务及依赖额外凭据配置的提供商不在此入口范围。上游连接在拨号时校验解析后的 IP，禁止回环、内网及元数据地址，不使用环境代理。

## 使用日志

`GET /api/log/self` 返回「调用者自己的日志」与「调用者拥有的分组的请求日志」的并集；计数、分页和 `GET /api/log/self/stat` 使用一致的所有权范围。

- 日志写入时记录 `group_owner_user_id`，不通过后来修改的渠道归属推断历史权限。
- 他人请求仅保留使用量、费用、模型、分组、时间、耗时和请求结果类型等基础信息，展示调用用户名，但清除用户 ID、令牌、IP、上游请求 ID、正文及扩展调试信息。
- 按令牌名称或上游请求 ID 查询时，只检索调用者自己的日志，防止借筛选条件探测他人隐私。
- 管理员原有全站日志权限不变。分成由管理员线下处理。

## API 与权限

| 方法与路径 | 权限 | 行为 |
| --- | --- | --- |
| `GET /api/personal/groups` | 登录用户 | 查看自己的分组 |
| `POST /api/personal/groups` | 登录用户 | 创建个人分组 |
| `PUT /api/personal/groups/:id` | 所有者 | 修改说明和倍率 |
| `GET /api/personal/channels` | 登录用户 | 分页查看自己的渠道和最新版本 |
| `POST /api/personal/channels` | 所有者 | 新建草稿或提交修改草稿，携带 `expected_revision_id` |
| `POST /api/personal/channels/:id/submit` | 所有者 | 提交指定 `revision_id` |
| `GET /api/personal-channel-reviews` | 管理员 + `channel.read` | 分页查看待审核版本 |
| `POST /api/personal-channel-reviews/:id` | 管理员 + `channel.sensitive_write` | 审批指定版本 |

写接口使用现有来源校验和关键操作限流。管理员审批使用现有敏感渠道写权限；普通管理员未获此权限时只能查看，超级管理员可审批。

启动迁移新增个人分组、个人渠道、渠道版本表，以及线上渠道归属列和日志归属列。主数据库使用 GORM 支持 SQLite、MySQL 和 PostgreSQL；独立日志数据库也执行迁移，ClickHouse 日志库使用兼容的新增列迁移。

## 上游模型选择

个人渠道表单支持获取上游模型后搜索、勾选、全选和清空，最多选择 200 个模型。模型获取使用 `POST /api/personal/channels/models`，支持 OpenAI/New API、Anthropic 和 Gemini 的模型列表及分页，设置请求超时、响应大小与页数限制。读取已保存的密钥时校验渠道所有权，且只向保存时相同的地址与提供商发送；地址或提供商改变后必须重新输入密钥。获取模型不会发布渠道或改变审核状态。

个人渠道不支持模型映射。模型列表中的名称直接作为提供服务的模型名称。
