# 月度总结

入口：个人 → 月度总结（`/monthly-recap`）。管理员在同一页面选择用户；所有读写接口均检查用户权限。

- 使用北京时间自然月，合并 `gpt-pro` 与 `gpt优惠`。次月 1 日零点开放上个月，默认选择最近一个已结束月份。服务端也拒绝当前月和未来月份。
- 第一次查询扫描保留日志并保存完整聚合 JSON；后续请求直接读取主数据库 `monthly_recap_snapshots`。空月份与不完整月份也会保存，并保留数据缺失提示。
- 唯一键是用户、月份和规则版本。规则版本标识分组范围及计算口径。保存内容包含模型、金额、使用习惯、计算时间和规则版本；不保存原始日志或用户敏感资料。
- 多实例通过数据库条件更新争抢一分钟计算租约，其他首次请求等待快照。请求计算上限为 30 秒；失败释放租约，进程中断后租约过期可恢复。已有快照在重算期间仍可读取。
- 管理员点击“重新计算总结”并确认后，使用当前仍保留的日志替换快照。失败不会清空旧快照。日志已删除时，重算可能得到更少的数据，无法恢复已删除日志。
- 快照按需生成，不自动为从未访问的用户归档日志。日志清理前未生成的月份可能不完整。跨月延迟写入的数据需要管理员重新计算才会包含。
- 数据表通过标准启动迁移创建，同时注册在普通和快速迁移路径，无历史回填任务。
- 月度荣誉「超值体验官」：完整月份的实际消费总额 ÷ 历史 1.0 倍率原价总额严格小于 0.15 时授予。等于 0.15 不授予；不平均各模型倍率，也不使用显示时四舍五入的数值判定。无最低请求数或活跃天数限制。
- 荣誉基准倍率为 0.25，节省比例为 `1 - 实际倍率 / 0.25`。原价必须为正，价格记录完整、无已知日志缺失或不可读记录，且当月存在用量；不满足数据要求时不评定。
- 荣誉规则版本、判定状态、称号代码、基准、门槛、实际倍率和节省比例一并保存在快照 JSON。旧快照不会自动改写，管理员重算后才补充荣誉；原始日志缺失时无法保证补发。无需新增数据库列。
- 下载纪念海报包含已获得的称号，不包含倍率或消费金额。

## API

- `GET /api/data/monthly-recap/self?month=YYYY-MM`：查看自己的快照，首次读取会创建。
- `GET /api/data/monthly-recap?user_id=ID&month=YYYY-MM`：管理员查看指定用户，共用同一份快照。
- `POST /api/data/monthly-recap/rebuild?user_id=ID&month=YYYY-MM`：管理员显式重新计算并替换。
- `GET /api/data/monthly-recap/users?keyword=...&page=1`：管理员搜索用户。

省略月份时默认为上个月。返回 `as_of` 为快照计算时间，`rule_version` 为聚合规则版本。`pricing_version=2` 按历史基础单价独立计算参考原价：未缓存输入 × 输入单价 + 缓存读取 × 缓存单价 + 输出 × 输出单价，另外计入缓存写入和有记录的工具费用。表达式计费使用日志中命中的历史档位单价；传统倍率计费使用日志中的 model_ratio、completion_ratio 等历史价格字段；按次计费用日志 model_price。分组折扣及请求加速倍率不参与基础原价，所以零扣费请求也有可计算的参考原价。不会读取当前价格配置。

动态单价依赖未保存的请求参数、档位不明确、特殊多模态用量不完整时保留“价格不可用”，不猜测。旧快照保留原结果并显示旧算法提示；管理员重算后写入 pricing_version=2，同时更新荣誉。此统计不修改实际扣费、余额或结算逻辑。

## 荣誉规则（版本 1）

每月一个主称号，按下表顺序首次命中即授予，另取最多两个成就徽章。只使用北京时间、所选两分组的消费日志；已知历史不完整、月份未结束或零用量时不授予。价格缺失只影响超值称号，不影响基于完整请求记录评定的使用习惯称号。

荣誉的“活跃日”定义为当天至少 3 次消费请求；与页面中有一次请求即记为活跃的常规统计分开显示。深度使用模型须至少 20 次请求、分布在至少 3 个不同日期。

| 优先级 | 主称号 | 条件 |
| --- | --- | --- |
| 1 | 超值体验官 | 完整价格记录、原价大于 0，实际月度倍率严格小于 0.15；基准为 0.25 |
| 2 | 月度常青树 | 活跃日达到当月天数的 80%，且连续活跃至少 7 天 |
| 3 | 模型探险家 | 深度使用至少 4 个模型 |
| 4 | 默契搭档 | 至少 100 次请求、7 个活跃日，某模型请求占比至少 80% |
| 5 | 深夜漫游者 | 至少 100 次请求、5 个活跃日，00:00–05:59 请求占比至少 50% |
| 6 | 晨光同行者 | 至少 100 次请求、5 个活跃日，06:00–11:59 请求占比至少 50% |
| 7 | 灵感实践家 | 至少 100 次请求、5 个活跃日 |
| 8 | 灵感拾光者 | 至少 1 次请求 |

徽章按顺序取前两个：全月相伴（每个自然日至少一次请求）、十四日不间断（连续 14 个活跃日）、千次回响（至少 1000 次请求）、上下文默契（输入至少一百万 token、缓存读取占比至少 90%、缓存统计有效）、多面探索（深度使用至少 3 个模型）。常青树不再发全月相伴或十四日徽章，模型探险家不再发多面探索，避免同一概念重复。
