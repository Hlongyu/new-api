# 用户请求限制

管理员在「系统设置 → 安全 → 用户请求限制」配置规则。限制以**用户所属分组**选择策略，计数按**用户 ID**隔离；渠道分组仍负责渠道选择，不改变用户身份。

## 请求池

每个用户有一个默认池，可以有多个 Key 分组专属池：

- Key 未指定分组，或该用户分组没有配置对应 Key 分组规则：进入默认池。
- Key 明确指定的分组命中专属规则：只进入该专属池。
- 专属规则整条替代默认规则，不叠加，也不为关闭的限制项回退到默认规则。
- 同一用户的多个 Key 指定同一分组时共享该专属池。未命中专属规则的多个分组共享默认池。
- 不同用户即使属于同一用户分组，也不共享计数。
- 本次不支持 `auto` 专属规则，也不根据最终渠道或重试结果重新选择请求池。

## 并发与速率

两项分别启用：

- **并发**：限制同时处理的 HTTP 请求数。流式请求占用到处理结束；完成、失败、取消退出和 panic 展开都会释放名额。一次请求内部的渠道重试不重复占用名额。异步任务提交或查询结束即释放，不追踪后台生成任务的生命周期。
- **速率**：滚动的 `n` 分钟内，最多接纳 `m` 个请求。已接纳但随后失败的请求也计数。
- 同时启用时原子检查两项。任一项超限直接返回 HTTP 429，不排队，也不消耗另一项额度。速率拒绝带 `Retry-After`（秒）。
- 错误代码分别为 `user_concurrency_limit_exceeded`、`user_rate_limit_exceeded`。计数服务不可用时返回 HTTP 503 和 `user_request_limit_unavailable`。
- 未配置的用户分组不受本功能限制。Web/API/IP 等其他限流中间件仍独立生效。
- 限制覆盖 `/v1` 模型请求（含 Realtime）、Gemini、Playground，以及已鉴权的视频、Suno、Midjourney 请求（包含任务查询）。模型列表和内容下载不占本功能的请求池。

## 配置示例

设置项 `UserRequestLimits` 保存整个 JSON 对象，前端通过一次保存更新完整策略。字段为非负整数；`0` 表示关闭该项。速率启用时窗口为 1～10080 分钟；并发与请求数最大为 2147483647。

```json
{
  "default": {
    "default": {
      "max_concurrent": 5,
      "rate_count": 60,
      "rate_window_minutes": 1
    },
    "key_groups": {
      "ds": {
        "max_concurrent": 10,
        "rate_count": 120,
        "rate_window_minutes": 1
      }
    }
  },
  "company": {
    "default": {
      "max_concurrent": 30,
      "rate_count": 0,
      "rate_window_minutes": 0
    },
    "key_groups": {
      "ds": {
        "max_concurrent": 50,
        "rate_count": 600,
        "rate_window_minutes": 1
      }
    }
  }
}
```

例如个人账户可同时处理 5 个默认池请求和 10 个 `ds` 请求。若专属规则只启用速率，则该专属池并发不限，不占用默认池并发。

## 旧配置切换

尚未保存 `UserRequestLimits` 时，已有 `ModelRequestRateLimit*` 规则继续按旧行为运行。界面在旧限流启用时显示提示及原有配置，便于核对。

首次保存新策略后，旧规则不再参与请求限制。不会自动将原先的渠道/Key 分组规则解释成用户分组规则。保存 `{}` 表示明确关闭本功能，不会回退到旧限流。原有配置保留在数据库中。

每个新请求读取当前策略；正在执行的请求保留已取得的名额。由不限流切换为启用限制时，不追溯之前未计数的请求。滑动窗口历史按原策略的有效期保留，修改窗口不会重建已经过期的历史。

## 部署

无 Redis 时使用进程内计数，适用于单实例。多实例必须共享 Redis 才能协调同一用户的限制；本机内存不会跨实例共享。

Redis 中的并发名额使用请求唯一标识及自动续期租约。请求退出删除自己的名额；进程崩溃后租约过期回收。续期失败会取消对应请求上下文并记录错误；Redis 不可用时不降级到本机计数，避免绕过共享限制。实例长时间暂停或网络分区导致租约丢失时，无法保证上游立刻停止计算，但本地会在检测到租约丢失后取消请求。
