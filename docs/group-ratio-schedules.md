# 分组倍率定时修改

在系统设置的「分组倍率」页面中，使用「分组倍率定时修改」添加单次计划：

1. 选择已经保存的目标分组。
2. 填写目标倍率（允许 0，不允许负数）。
3. 选择执行日期和时间。界面始终使用北京时间 UTC+8，与浏览器和服务器所在时区无关。
4. 点击「添加单次定时修改」。该操作立即保存计划，不需要再点击页面顶部的倍率保存按钮。

例如 `gpt-pro`、`0.1`、`2026-10-25 00:00` 表示北京时间周日零点执行一次，对应 UTC `2026-10-24 16:00`。它不会每周重复，也不会自动恢复原倍率；如需恢复，请再创建一个后续计划。示例不会由部署过程自动创建。

计划只修改基础分组倍率（`GroupRatio`），不修改充值倍率或专属分组倍率。专属分组倍率仍按现有计费优先级生效。

## 执行与恢复

- 只有 root 管理员可以查看、创建和取消计划。待执行计划可以取消；已执行、失败和取消记录保留在历史列表中。
- 同一分组、同一执行时间不允许存在多条待执行计划。修改计划请先取消旧计划，再创建新计划。
- 主节点每秒检查一次到期计划，正常运行时通常在到期后一秒左右开始处理；这不是硬实时保证。多个主节点通过数据库锁和条件更新避免重复执行。其他实例继续通过现有 `SyncOptions` 同步配置，其生效时间受 `SyncFrequency` 影响。
- 计划保存到数据库。服务停机时不会执行；重启后按原定执行时间和 ID 顺序补执行到期计划。
- 执行时读取数据库中的最新倍率，只修改目标分组，保留其他分组的后续修改。
- 倍率、配置别名、webhook 待发送事件和计划完成状态在同一事务内提交。数据库错误会回滚，计划保持待执行并自动重试。
- 如果目标分组在执行前已删除，计划标记为失败，不会重新创建分组。
- 历史记录包含计划时间、完成时间、原倍率和目标倍率。界面列表每 10 秒刷新；当前倍率表沿用原有加载机制，执行后重新加载设置即可查看新值。

## 管理 API

沿用 `/api/option` 的 root 鉴权：

- `GET /api/option/group-ratio-schedules?status=pending&page=1`
- `GET /api/option/group-ratio-schedules?status=history&page=1`
- `POST /api/option/group-ratio-schedules`，JSON：`{"group":"gpt-pro","ratio":0.1,"execute_at":1792857600}`。`execute_at` 为 Unix 秒，必须在未来。
- `POST /api/option/group-ratio-schedules/:id/cancel`

列表每页 20 条，返回 `data.items` 与 `data.total`。创建和取消操作记录管理审计。部署启动时自动迁移 `group_ratio_schedules` 表，保留现有倍率和其他数据。
